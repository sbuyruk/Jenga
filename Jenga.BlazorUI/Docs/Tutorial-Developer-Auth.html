1. Genel Mimari

Sistem iki katmanlı bir yetkilendirme modelinden oluşur:

┌─────────────────────────────────────────────────────────────────┐ │ KİMLİK DOĞRULAMA (Authentication) │ │ Hibrit: Windows Negotiate (intranet) + Cookie/LDAP (internet) │ ├─────────────────────────────────────────────────────────────────┤ │ YETKİLENDİRME (Authorization) — 2 Boyut │ │ │ │ 1. Modül-Operasyon İzinleri ────► ne yapabilir? │ │ Personel → Rol → RoleModulePermission → ModulePermission │ │ │ │ 2. Bölge İzinleri ────► nerede yapabilir? │ │ Personel → PersonnelRegionPermission → Bolge │ └─────────────────────────────────────────────────────────────────┘

Tüm yetkilendirme işlemleri ICurrentUserService arayüzü üzerinden yürütülür. Servis Scoped olarak kayıtlıdır; her Blazor circuit (WebSocket bağlantısı) için ayrı bir instance oluşturulur.

2. Kimlik Doğrulama (Authentication)

2.1 Hibrit PolicyScheme

Program.cs'te "JengaAuth" adlı bir PolicyScheme forwarder tanımlıdır. Her HTTP isteğinde aşağıdaki öncelik sırası işletilir:

İstek geldi │ ├─ Cookie ".Jenga.Auth" mevcut? → CookieScheme (internet / mobil) ├─ Authorization: Negotiate/NTLM başlığı?→ NegotiateScheme (Windows SSO) ├─ İntranet IP + masaüstü tarayıcı? → NegotiateScheme (challenge gönder) └─ Diğer → CookieScheme (login sayfasına yönlendir)

2.2 LDAP / Cookie Akışı (internet)

LdapAuthenticator servisi System.DirectoryServices.AccountManagement kullanarak Active Directory'ye karşı doğrulama yapar:

POST /auth/login
  → LdapAuthenticator.ValidateCredentials(userName, password)
      → PrincipalContext(ContextType.Domain, "tskgv.org.tr")
      → UserPrincipal.FindByIdentity → ValidateCredentials
  ← true ise ClaimsPrincipal oluştur, ".Jenga.Auth" cookie'si yaz
  ← false ise 401 / login formuna geri dön

Config (appsettings.json):

"Auth": {
  "Ldap": {
    "Domain":         "tskgv.org.tr",   // FQDN
    "DomainFallback": "TSKGV",          // NetBIOS fallback
    "Container":      null              // null = tüm domain
  }
}

2.3 Cookie Ayarları

o.Cookie.Name         = ".Jenga.Auth"
o.Cookie.HttpOnly     = true
o.Cookie.SameSite     = SameSiteMode.Lax
o.ExpireTimeSpan      = TimeSpan.FromDays(30)
o.SlidingExpiration   = true
o.Cookie.MaxAge       = TimeSpan.FromDays(30)  // iOS Safari kalıcılığı

2.4 Negotiate (intranet)

IIS + Kerberos/NTLM — kullanıcı şifre girmez. AddNegotiate() middleware token'ı çözümler. Mobil cihazlar VPN üzerinden intranet IP alsa da IsMobileBrowser() kontrolü ile Cookie akışına yönlendirilir.

⚠️ Güvenlik Notu Environment.UserName fallback kasıtlı olarak kaldırılmıştır. Eski haliyle Negotiate auth başarısız olduğunda uygulama havuzu hesabı personel olarak çözümlenebiliyordu (auth-bypass). Şimdi başarısız auth → null döner.

4. ModuleName ve Operation Enum'ları

public enum ModuleName
{
    TBYS      = 0,
    NBYS      = 1,
    FTK       = 2,
    IKYS      = 3,
    Inventory = 4,
    Admin     = 5
}

public enum Operation
{
    View   = 0,
    Create = 1,
    Edit   = 2,
    Delete = 3,
    Manage = 4   // ← Üst-izin: aynı modüldeki tüm operasyonları kapsar
}
💡 Manage Kuralı HasPermissionAsync(module, anyOperation) çağrıldığında, kullanıcı o modülde Manage iznine sahipse her zaman true döner. Yani Manage verildiyse View, Create, Edit, Delete'i ayrıca tanımlamak gerekmez. 
// CurrentUserService.cs
public async Task<bool> HasPermissionAsync(ModuleName module, Operation operation)
{
    var permissions = await GetModulePermissionsAsync();
    return permissions.Contains((module, operation))
        || permissions.Contains((module, Operation.Manage)); // ← üst-izin kontrolü
}

5. ICurrentUserService ve Yaşam Döngüsü

5.1 Arayüz

public interface ICurrentUserService
{
    // Prerender / JS hazır değilken (impersonation atlanır)
    Task<Personel?> GetCurrentPersonelWithoutImpersonationAsync();

    // Normal çağrı (impersonation dahil)
    Task<Personel?> GetCurrentPersonelAsync();

    // DB sorgusu yapmaz; audit için
    Task<string?> GetUserNameAsync();

    // Cache temizleme
    void Invalidate();

    // Dev-only impersonation
    Task<bool> SetImpersonationOverrideAsync(string? overrideUser);

    // HashSet<(ModuleName, Operation)> döner — önbelleklenir
    Task<IReadOnlySet<(ModuleName Module, Operation Operation)>> GetModulePermissionsAsync();

    // Yetkili bölge ID listesi — önbelleklenir
    Task<IReadOnlyList<int>> GetAuthorizedRegionIdsAsync();

    // Manage üst-iznini de değerlendirir
    Task<bool> HasPermissionAsync(ModuleName module, Operation operation);
}

5.2 Kayıt (DI)

// BlazorUIServiceExtensions.cs
services.AddScoped<ICurrentUserService, CurrentUserService>();

Scoped = Her Blazor circuit için tek instance. Kullanıcı sekmeyi kapattığında / circuit kesildiğinde dispose edilir.

5.3 Cache Stratejisi — Double-Check Lock

İlk çağrı │ ├─ Volatile.Read(_cachedPersonel) != null → hızlı dön (lock-free) │ └─ null → SemaphoreSlim.WaitAsync() │ ├─ tekrar kontrol (başka thread yazdı mı?) │ └─ DB sorgusu → _cachedPersonel = sonuç _cacheLock.Release() Invalidate() çağrılırsa: _cachedPersonel = null (Volatile.Write) _cachedPermissions = null _cachedRegionIds = null _impersonationChecked = false

5.4 Prerender / JS-Interop Sorunu

// skipImpersonation = true  → prerender aşamasında impersonation atlanır
// skipImpersonation = false → interaktif aşamada JS hazır mı dene
//
// JS hazır değilse → null dön, CACHE'LEME

if (!impersonationJsAvailable)
    return null;   // ← gerçek kullanıcı cache'e YAZILMAZ

5.5 GetModulePermissionsAsync — Tek Round-Trip Join

var result = await (
    from pr  in db.PersonelRol_Table.AsNoTracking()
    join rmp in db.RoleModulePermission_Table.AsNoTracking()
        on pr.RoleId equals rmp.RoleId
    join mp  in db.ModulePermission_Table.AsNoTracking()
        on rmp.ModulePermissionId equals mp.Id
    where pr.PersonelId == personel.Id
    select new { mp.Module, mp.Operation }
).Distinct().ToListAsync();

_cachedPermissions = result
    .Select(p => (p.Module, p.Operation))
    .ToHashSet();   // O(1) lookup

5.6 GetAuthorizedRegionIdsAsync

var regionIds = await db.PersonnelRegionPermission_Table
    .AsNoTracking()
    .Where(prp => prp.PersonnelId == personel.Id)
    .Select(prp => prp.RegionId)
    .ToListAsync();

Boş liste → kullanıcıya henüz bölge atanmamış demektir.

6. IServiceAuthorizationContext — Katman Köprüsü

DataAccess katmanı Blazor UI'ya bağımlı olamaz. Bu yüzden bir interface segregation köprüsü kullanılır:

// DataAccess katmanı (Blazor bağımlılığı yok)
public interface IServiceAuthorizationContext
{
    Task<bool>    HasPermissionAsync(ModuleName module, Operation operation, CancellationToken ct);
    Task<string?> GetUserNameAsync(CancellationToken ct);
}

// BlazorUI implementasyonu — ICurrentUserService üzerine yönlendirir
public sealed class BlazorServiceAuthorizationContext : IServiceAuthorizationContext
{
    private readonly ICurrentUserService _currentUserService;

    public Task<bool> HasPermissionAsync(ModuleName module, Operation operation, CancellationToken ct)
        => _currentUserService.HasPermissionAsync(module, operation);

    public Task<string?> GetUserNameAsync(CancellationToken ct)
        => _currentUserService.GetUserNameAsync();
}

// DI kaydı
services.AddScoped<IServiceAuthorizationContext, BlazorServiceAuthorizationContext>();

10. Impersonation (Sadece Development)

// SwitchUser.razor üzerinden
await CurrentUserService.SetImpersonationOverrideAsync("testkullanici");
  • Production'da IHostEnvironment.IsDevelopment() kontrolü ile kesin engellenir.
  • Override değeri ImpersonationService aracılığıyla browser sessionStorage'a yazılır (JS interop).
  • Cache ataması _cacheLock içinde atomik yapılır: DB sorgusu ile atama arasındaki pencerede gerçek kullanıcının cache'e yazılması önlenir.
  • Invalidate() çağrıldığında tüm cache temizlenir.
// Atomik cache ataması
await _cacheLock.WaitAsync();
try {
    _cachedPersonel    = found;
    _cachedPermissions = null;   // yeni personelin izinleri yeniden yüklensin
    _cachedRegionIds   = null;
    _impersonationChecked = true;
}
finally { _cacheLock.Release(); }

11. Authorization Fallback Policy

// Program.cs
options.FallbackPolicy = new AuthorizationPolicyBuilder(PolicyScheme)
    .RequireAuthenticatedUser()
    .Build();
